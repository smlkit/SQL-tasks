Набор из 60 SQL-задач среднего и продвинутого уровня на датасете маркетплейса.

## Темы

В заданиях используются:

- `INNER JOIN`
- `LEFT JOIN`
- `RIGHT JOIN`
- `ANTI JOIN`
- `SELF JOIN`
- `EXISTS`
- `NOT EXISTS`
- агрегатные функции
- `CASE WHEN`
- `CASE` внутри агрегатных функций
- вложенные запросы
- `CTE`
- оконные функции
- оконные frame'ы

# Database Schema

Основные таблицы:

```text
customers
    │
    ├───────────────┐
    │               │
    ▼               ▼
orders ──────── payments
    │
    ├────────── deliveries
    │
    ├────────── returns
    │
    └──── order_items ───── products ───── categories
              │
              │
              └──────── sellers

orders ───── reviews
orders ───── promo_codes
```

Дополнительные связи:

```text
customers.referred_by → customers.customer_id

sellers.parent_seller_id → sellers.seller_id

categories.parent_category_id → categories.category_id
```

# Part 1 — JOIN + Aggregation + CASE

## 1. Выручка продавцов

Для каждого продавца рассчитать:

- название продавца;
- количество `completed` заказов;
- количество проданных товаров;
- общую выручку;
- среднюю стоимость заказа;
- среднюю маржу.

Использовать минимум следующие таблицы:

- `orders`;
- `order_items`;
- `products`;
- `sellers`.

Стоимость позиции должна учитывать скидку:

```text
quantity * unit_price * (1 - discount_percent / 100)
```

---

## 2. Прибыль продавцов

Для каждого продавца рассчитать:

- `revenue`;
- `cost`;
- `profit`;
- `profit_margin`.

Где:

```text
revenue =
quantity * unit_price * (1 - discount_percent / 100)

cost =
quantity * cost_price

profit =
revenue - cost
```

Учитывать только `completed` заказы.

---

## 3. Категории с высокой маржой

Для каждой категории рассчитать:

- количество товаров;
- количество проданных единиц;
- выручку;
- прибыль;
- среднюю маржу.

Вывести только категории, где:

```text
profit_margin > 20%
```

---

## 4. Продавцы с возвратами

Для каждого продавца рассчитать:

- количество проданных единиц;
- количество возвращённых единиц;
- процент возврата.

Использовать `LEFT JOIN`, чтобы продавцы без возвратов также присутствовали в результате.

---

## 5. Условная агрегация по статусам заказов

Для каждого клиента посчитать в одной строке:

- количество всех заказов;
- количество `completed`;
- количество `cancelled`;
- количество `processing`;
- сумму `completed` заказов.

Использовать `CASE` внутри агрегатных функций.

---

## 6. Клиенты с высоким LTV

Для каждого клиента рассчитать:

- количество `completed` заказов;
- общую выручку;
- средний чек;
- количество возвращённых товаров.

Затем классифицировать клиентов:

| Revenue | Segment |
|---:|---|
| `>= 200000` | VIP |
| `>= 100000` | Premium |
| `>= 50000` | Regular |
| `< 50000` | Low |

Использовать `CASE`.

---

## 7. Анализ промокодов

Для каждого промокода вывести:

- количество заказов;
- количество `completed` заказов;
- сумму выручки;
- среднюю сумму заказа;
- количество клиентов, использовавших промокод.

Промокоды, которые ни разу не использовались, также должны присутствовать в результате.

## 8. Продавцы выше среднего

Найти продавцов, чья средняя стоимость `completed` заказа выше средней стоимости заказа по всему marketplace.

Использовать:

- `JOIN`;
- `GROUP BY`;
- `HAVING`;
- вложенный запрос или CTE.

---

## 9. Товары без продаж

Найти товары, которые:

- существуют в таблице `products`;
- имеют положительный остаток на складе;
- ни разу не продавались.

Использовать `ANTI JOIN`.

---

## 10. Товары без отзывов

Найти товары, которые хотя бы один раз продавались, но не имеют ни одного отзыва.

Использовать комбинацию:

- `JOIN`;
- `NOT EXISTS`.

# Part 2 — EXISTS / NOT EXISTS / Subqueries

## 11. VIP-клиенты

Найти клиентов, у которых одновременно:

- существует хотя бы один заказ стоимостью более `100000`;
- существует хотя бы один `completed` заказ;
- нет ни одного `cancelled` заказа.

Использовать `EXISTS` и `NOT EXISTS`.

---

## 12. Продавцы без возвратов

Найти продавцов, у которых:

- был хотя бы один `completed` заказ;

- отсутствуют возвраты.

Использовать `EXISTS` и `NOT EXISTS`.

## 13. Клиенты с повторной покупкой

Не использовать `COUNT()`.

Использовать `EXISTS`.

## 14. Товары, продававшиеся нескольким клиентам

Использовать вложенный запрос.

## 17. Самый дорогой товар продавца

## 18. Продавцы с дорогими товарами
