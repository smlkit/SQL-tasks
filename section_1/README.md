# SQL Practice — Online School Database

Практический набор SQL-задач для отработки:

* `INNER JOIN`
* `LEFT JOIN`
* `RIGHT JOIN`
* `ANTI JOIN`
* `SELF JOIN`
* агрегатных функций
* `GROUP BY` / `HAVING`
* `CASE WHEN`
* `WHERE EXISTS`
* `WHERE NOT EXISTS`
* вложенных запросов
* `CTE`
* `VIEW`
* `CTAS`
* оконных функций

## Описание

В этом проекте используется учебная база данных онлайн-школы.

Основные сущности:

* студенты;
* преподаватели;
* курсы;
* группы;
* записи студентов на курсы;
* занятия;
* оценки;
* платежи.

Схема специально содержит связи, позволяющие практиковать как простые `JOIN`, так и более сложные комбинации нескольких SQL-концепций.

# 🟢 Уровень 1 — JOIN

## 1. Список студентов и их курсов

Вывести список всех студентов, которые записались хотя бы на один курс.

Показать:

* имя и фамилию студента;
* название группы;
* дату записи;
* статус записи.

Использовать `INNER JOIN`.

---

## 2. Информация о записях на курсы

Получить список всех записей студентов на курсы.

Показать:

* студента;
* группу;
* курс;
* преподавателя;
* уровень курса;
* цену курса.

Использовать несколько `INNER JOIN`.

---

## 3. Все студенты и количество курсов

Вывести всех студентов и количество курсов, на которые они записались.

Студенты без записей также должны присутствовать в результате.

Использовать `LEFT JOIN`.

---

## 4. Все студенты и completed-курсы

Вывести всех студентов и количество их завершённых (`completed`) курсов.

Студенты без завершённых курсов также должны присутствовать в результате.

---

## 5. Все курсы и количество групп

Получить список всех курсов и количество групп, созданных для каждого курса.

Использовать `RIGHT JOIN`.

Курсы без групп также должны отображаться.

---

## 6. Преподаватели и их группы

Для каждого преподавателя показать:

* имя преподавателя;
* количество групп;
* количество студентов в его группах.

Преподаватели без групп также должны присутствовать в результате.

Использовать `LEFT JOIN`.

---

## 7. Студенты без курсов

Найти студентов, которые никогда не записывались ни на один курс.

Решить задачу через `LEFT JOIN` и проверку `NULL`.

Это задача на `ANTI JOIN`.

---

## 8. Курсы без групп

Найти курсы, для которых нет ни одной группы.

Использовать `LEFT JOIN`.

---

## 9. Преподаватель и руководитель

Вывести каждого преподавателя и его руководителя.

Результат должен содержать:

* преподавателя;
* руководителя.

Если у преподавателя нет руководителя, он всё равно должен присутствовать в результате.

Использовать `SELF JOIN`.

---

## 10. Преподаватели с высокой зарплатой

Найти преподавателей, которые получают больше своего руководителя.

Показать:

* имя преподавателя;

* зарплату руководителя.

Использовать `SELF JOIN`.

# 🟡 Уровень 3 — CASE WHEN

## 18. Категория цены курса

Для каждого курса создать категорию цены:

| Цена          | Категория |
| ------------- | --------- |
| `< 30000`     | Дешёвый   |
| `30000–49999` | Средний   |
| `50000–69999` | Дорогой   |
| `>= 70000`    | Премиум   |

Использовать `CASE WHEN`.

---

## 19. Результат обучения

Для каждого студента определить результат обучения на основании `final_score`:

| Балл    | Результат         |
| ------- | ----------------- |
| `>= 90` | Отлично           |
| `80–89` | Хорошо            |
| `60–79` | Удовлетворительно |
| `< 60`  | Не сдал           |

Использовать `CASE WHEN`.

---

## 20. Успешные и неуспешные студенты

Для каждого курса посчитать:

* общее количество студентов;
* количество студентов с результатом `>= 90`;
* количество студентов с результатом `< 60`.

Использовать `CASE` внутри агрегатной функции.

Например, можно использовать конструкцию:

```sql
SUM(
    CASE
        WHEN ...
        THEN 1
        ELSE 0
    END
)
```

---

## 21. Платежи по способу оплаты

Для каждого курса посчитать:

* сумму всех оплаченных платежей;
* сумму платежей картой;
* сумму платежей наличными.

Использовать `CASE` внутри `SUM()`.

## 22. Статус студента

* `VIP` — минимум 2 завершённых курса и минимум 2 оплаченных платежа;

* `Новый` — есть только активная запись;

Использовать `CASE WHEN`.

Для определения статуса потребуется объединить несколько источников данных и использовать агрегаты.

# 🔵 Уровень 7 — Оконные функции

## 38. ROW_NUMBER — история обучения

Для каждого студента пронумеровать его записи на курсы от самой новой к самой старой.

Получить:

* студента;
* курс;
* дату записи;
* порядковый номер записи.

Использовать:

```sql
ROW_NUMBER() OVER (
    PARTITION BY student_id
    ORDER BY enrollment_date DESC
)
```

---

## 39. RANK — рейтинг студентов

Составить рейтинг студентов по их среднему итоговому баллу.

Вывести:

* студента;
* средний балл;
* место в рейтинге.

---

## 40. RANK — рейтинг внутри курса

Для каждого курса составить рейтинг студентов по `final_score`.

Результат должен содержать:

* курс;
* студента;
* итоговый балл;
* место.

Использовать:

```sql
RANK() OVER (
    PARTITION BY course_id
    ORDER BY final_score DESC
)
```

После этого оставить только студентов, занявших первое место в каждом курсе.

## 44. Финальная задача — Course Performance Report

Сформировать итоговый аналитический отчёт по курсам.

Для каждого курса вывести:

* название курса;
* категорию;
* уровень;
* цену;
* количество студентов;
* средний балл;
* процент студентов с баллом `>= 80`;
* количество завершивших курс;
* количество отменённых записей;
* общую сумму оплаченных платежей;
* место курса внутри категории по выручке.

### Дополнительные требования

1. Курсы без студентов не должны исчезнуть из результата.
2. Для подсчёта успешных студентов использовать `CASE` внутри агрегатной функции.
3. Для расчёта выручки использовать `CASE` внутри `SUM()`.
4. Для рейтинга использовать `RANK()`.
5. Рейтинг должен рассчитываться отдельно внутри каждой категории.
6. Постарайтесь решить задачу так, чтобы не использовать коррелированные подзапросы там, где можно обойтись `JOIN` + `GROUP BY`.

### Используемые темы

```text
LEFT JOIN
    ↓
GROUP BY
    ↓
CASE WHEN
    ↓
CASE внутри SUM / COUNT
    ↓
RANK() OVER (PARTITION BY ...)
```
